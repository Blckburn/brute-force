# Генерация арта для BRUTEFORCE 3D

## Прежде чем начать

Прочитай `docs/ART-BIBLE.md`. Это источник истины по стилю, границам и техтребованиям. Если инструкции ниже противоречат арт-библии — прав документ, а не этот скилл. Расхождение — сообщи пользователю, не решай сам.

Прочитай `packages/data/assets.json` — текущий манифест. И посмотри уже существующие файлы в `apps/web/public/assets/icons/`: новые ассеты должны быть в одном стиле с ними, а не с текстовым описанием стиля.

## Территория

Ты работаешь в репозитории вместе с другим агентом, который пишет код. Ты владеешь **только**:

- `apps/web/public/assets/**`
- `packages/data/assets.json`
- `docs/art/**`

Всё остальное — чужое. Не редактируй код, конфиги, схему БД, `packages/sim`, `docs/GDD-2.0.md`. Понадобилось изменение вне твоей зоны — опиши его пользователю и остановись.

В `assets.json` ты **только добавляешь и правишь записи**. Не меняй структуру файла, не переименовывай ключи, не сортируй заново — этот файл читает тест в CI.

## Процесс

### 1. Определи пачку

Работай **одной категорией за запуск**. Категории: `weapons`, `offhands`, `armor`, `accessories`, `statuses`, `traits`, `portraits`, `zones`, `ui`.

Причина: дрейф стиля между сессиями — главный источник несогласованности набора. Все иконки оружия должны родиться в одном заходе.

Список нужных сущностей бери из `packages/data` — из таблиц предметов, статусов и трейтов, а не из головы. Если данных ещё нет, спроси у пользователя список.

### 2. Собери промпт

Базовая часть зафиксирована в `docs/ART-BIBLE.md`, раздел 2. Не переписывай её и не «улучшай». Подставляй только описание конкретного предмета.

Если для этой категории уже есть файл `docs/art/prompts/{категория}.md` — используй промпт оттуда дословно.

### 3. Сгенерируй

Через `$imagegen`. Для каждой сущности: 1024×1024, прозрачный фон, без текста.

Первым делом сгенерируй **три пробных** и покажи пользователю. Дождись подтверждения стиля, только потом гони остальные. Не генерируй тридцать иконок, не показав ни одной.

### 4. Проверь

Каждый ассет проходит две проверки, обе обязательны:

- **Читаемость в 48px.** Уменьши и посмотри сам. Не опознаётся, что это за предмет, — перегенерируй. Мобильный интерфейс первичен, в инвентаре иконка мелкая.
- **Прозрачность фона.** Никаких белых или цветных подложек.

Не принимай ассет, потому что «в целом нормально». Отклонённый ассет дешевле перегенерировать, чем переделывать набор потом.

### 5. Обработай

```
исходник  → docs/art/source/{категория}/{имя}.png   (1024, PNG, в git)
продакшн  → apps/web/public/assets/icons/{категория}/{имя}.webp  (256)
            apps/web/public/assets/icons/{категория}/{имя}@small.webp  (128)
```

Используй `sharp` или ImageMagick. Целевой вес WebP 256 — под 20 КБ. Не влезает — сжимай сильнее, не увеличивай бюджет.

Именование: `kebab-case`, латиница, совпадает с ключом сущности в `packages/data`. Меч с `base_key: "weapon.sword"` → файл `sword.webp` в папке `weapons`.

### 6. Зарегистрируй

Добавь записи в `packages/data/assets.json`:

```json
"weapon.sword": "icons/weapons/sword.webp"
```

Путь относительно `apps/web/public/assets/`.

### 7. Сохрани промпты

В `docs/art/prompts/{категория}.md`: использованный промпт целиком, модель, дата, любые отклонения от базового промпта. Через месяц понадобится догенерировать одну иконку в том же стиле — без этого файла не выйдет.

### 8. Закоммить

```bash
git checkout -b art/{категория}
git add apps/web/public/assets packages/data/assets.json docs/art
git commit -m "assets: {категория} icons"
git push -u origin art/{категория}
```

Открой PR. **В `main` не пушь никогда.** В репозитории параллельно работает другой агент, прямой пуш в `main` создаст конфликты.

Перед коммитом сделай `git pull --rebase origin main` — репозиторий мог уйти вперёд.

## Запреты

- Не запекай редкость в иконку. Одна иконка на базовый тип. Рамки, свечение и цвет редкости рисует UI. Иначе набор вырастет впятеро
- Не рисуй текст, цифры и подписи внутри изображений — ломает локализацию RU/EN
- Не пытайся генерировать 3D-модели, риги, окружение арены, партиклы и анимации. Это процедурная геометрия three.js, не растр. Раздел 1 арт-библии
- Не меняй базовый промпт по своему усмотрению
- Не удаляй и не перезаписывай существующие ассеты без явной просьбы
- Не добавляй зависимости в `package.json`

## Готово, когда

Ассеты лежат в двух разрешениях, все прошли проверку на 48px, зарегистрированы в манифесте, промпты сохранены, PR открыт, `main` не тронут.
