# Исходники иконок

Сюда кладутся **PNG 1024×1024 с прозрачным фоном**. Обработку делает
`pnpm assets:build` — он приводит их к продакшн-виду и сам вписывает пути
в `packages/data/assets.json`.

```
assets-src/<категория>/<идентификатор>.png
```

Имя папки — категория, имя файла — идентификатор сущности. Пример:

```
assets-src/zones/wastes.png   ->  ключ zone.wastes
assets-src/statuses/bleed.png ->  ключ status.bleed
```

Соответствие папок категориям — в `scripts/process-assets.mjs`,
константа `CATEGORY_BY_DIR`.

## Что происходит при обработке

| Шаг                           | ART-BIBLE                  |
| ----------------------------- | -------------------------- |
| PNG 1024 -> WebP 256 и 128    | §3                         |
| проверка альфа-канала         | §3                         |
| проверка прозрачности углов   | §3, подложка не запекается |
| проверка веса под 20 КБ       | §3                         |
| проверка kebab-case латиницей | §3                         |
| запись пути в манифест        | §4                         |

Ассет, не прошедший проверку, **не принимается**: скрипт называет причину
и возвращает ненулевой код.

## Пустая папка — нормально

Игра собирается и работает с нулём готовых иконок: на их месте
рисуются плейсхолдеры (ART-BIBLE §4). Файлы здесь появляются пачками
по категориям, как описано в §5.

## Расхождение с ART-BIBLE

§3 документа говорит «Исходник PNG, 512×512», а конвейер требует 1024.
Это сознательное решение человека, принятое позже документа. Правку
в `docs/ART-BIBLE.md` вносит человек — агенты документы не редактируют.
