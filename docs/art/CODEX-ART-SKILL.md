# Генерация арта для EXTRA MUNDUM

## Прежде чем начать

Прочитай `docs/ART-BIBLE.md` целиком. Это источник истины по стилю, границам и техтребованиям. Если инструкции ниже противоречат арт-библии — прав документ, а не этот скилл. Расхождение — сообщи, не решай сам.

Прочитай `docs/LORE.md` — стиль вытекает из мира, а не наоборот.

Прочитай `packages/data/assets.json` — текущий манифест. И посмотри уже существующие файлы в `apps/web/public/assets/icons/`: новые ассеты должны быть в одном стиле с ними, а не с текстовым описанием стиля.

## Территория

В репозитории параллельно работает другой агент, который пишет код. Ты владеешь **только**:

- `apps/web/public/assets/**`
- `packages/data/assets.json`
- `docs/art/**`

Всё остальное — чужое. Не редактируй код, конфиги, схему БД, `packages/sim`, `packages/data` кроме манифеста, `docs/GDD-2.0.md`, `docs/LORE.md`, `docs/ART-BIBLE.md`.

Перед каждым коммитом делай `git pull --rebase origin main` — репозиторий активно уходит вперёд.

В `assets.json` **только добавляй и правь записи**. Не меняй структуру файла, не переименовывай ключи, не сортируй заново — его читает тест в CI.

## Процесс

### 1. Определи пачку

Работай **одной категорией за запуск**: `weapons`, `offhands`, `armor`, `accessories`, `statuses`, `traits`, `portraits`, `settlers`, `buildings`, `zones`, `ui`.

Дрейф стиля между сессиями — главный источник несогласованности набора. Все иконки оружия должны родиться в одном заходе.

Список сущностей бери из `packages/data` — из таблиц предметов, статусов и трейтов, а не из головы. Данных ещё нет — спроси список.

### 2. Собери промпт

Базовая часть зафиксирована в `docs/ART-BIBLE.md`, раздел 2. Не переписывай её и не улучшай. Подставляй только описание предмета.

Если для категории уже есть `docs/art/prompts/{категория}.md` — используй промпт оттуда дословно.

### 3. Сгенерируй

1024×1024, прозрачный фон, без текста.

Первым делом сгенерируй **три пробных** и покажи. Дождись подтверждения стиля, только потом гони остальные. Не генерируй тридцать иконок, не показав ни одной.

### 4. Проверь

Три обязательные проверки:

- **Читаемость в 48px.** Уменьши и посмотри сам. Не опознаётся — перегенерируй. Гравюрный стиль здесь рискованнее плоского: штриховка легко превращается в кашу. Это главный риск направления, см. арт-библию, раздел 10, вопрос 4
- **Прозрачность фона.** Никаких подложек, кругов, рамок. Они часть интерфейса, а не иконки
- **Золото.** Тёплое золото и чистая белизна зарезервированы за вещами из Мунды (арт-библия, раздел 3). Обычный предмет золота не содержит — кость, пепел, охра, запёкшийся красный

Не принимай ассет, потому что «в целом нормально». Перегенерировать дешевле, чем переделывать набор.

### 5. Обработай

```
исходник  → docs/art/source/{категория}/{имя}.png       (1024, PNG, в git)
продакшн  → apps/web/public/assets/icons/{категория}/{имя}.webp        (256)
            apps/web/public/assets/icons/{категория}/{имя}@small.webp  (128)
```

`sharp` или ImageMagick. Вес WebP 256 — под 20 КБ. Не влезает — сжимай сильнее, бюджет не двигай.

Именование: `kebab-case`, латиница, совпадает с ключом сущности в `packages/data`.

### 6. Зарегистрируй

```json
"weapon.sword": "icons/weapons/sword.webp"
```

Путь относительно `apps/web/public/assets/`.

### 7. Сохрани промпты

В `docs/art/prompts/{категория}.md`: промпт целиком, модель, дата, отклонения от базового. Через месяц понадобится догенерировать одну иконку в том же стиле — без этого файла не выйдет.

### 8. Закоммить

```bash
git pull --rebase origin main
git checkout -b art/{категория}
git add apps/web/public/assets packages/data/assets.json docs/art
git commit -m "assets: {категория} icons"
git push -u origin art/{категория}
```

Открой PR. **В `main` не пушь никогда.**

## Запреты

- Не запекай редкость в иконку. Одна иконка на базовый тип. Рамки, свечение и цвет редкости рисует UI
- Не рисуй текст, цифры и подписи внутри изображений — ломает локализацию RU/EN
- Не используй градиенты, глянцевые блики и насыщенные чистые цвета. Это направление отменено вместе с версией 1.0 арт-библии
- Не генерируй 3D-модели, риги, окружение арены, партиклы и анимации. Это процедурная геометрия, не растр
- Не меняй базовый промпт по своему усмотрению
- Не удаляй и не перезаписывай существующие ассеты без явной просьбы
- Не добавляй зависимостей в `package.json`

## Готово, когда

Ассеты лежат в двух разрешениях, все прошли три проверки, зарегистрированы в манифесте, промпты сохранены, PR открыт, `main` не тронут.
