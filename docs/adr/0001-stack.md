# ADR 0001 — Хостинг и стек

**Дата:** 2026-08-17
**Статус:** принято

## Контекст

GDD 2.0 писался с расчётом на Supabase Edge Functions. После того как был
зафиксирован сервер-авторитет, выяснилось, что половина преимуществ Supabase
для нас не работает.

## Решение

Render (сервер и статика) + Neon (Postgres) + Hono + Drizzle + Better Auth.

## Почему не Supabase

- **RLS перестаёт быть преимуществом.** Его смысл — безопасно пускать клиент
  писать напрямую. Мы решили не пускать. RLS сводится к «клиенту всё
  запрещено», и остаётся соблазн сделать исключение — как в v1.0
- **Realtime не нужен.** Арена асинхронная, бой считается одним вызовом
- **Долгоживущий процесс лучше edge-функции.** Движок — чистый TS без I/O.
  На тёплом Node нет холодных стартов и лимитов CPU, а географическая
  близость к пользователю нам безразлична: регион один
- **Neon даёт ветвление базы** на каждый PR. Для проекта с частыми
  миграциями схемы предметов это существенно

## Цена решения

Теряем встроенную авторизацию — закрывается Better Auth.
Render Web Service на Free засыпает после 15 минут простоя, нужен
Starter ($7/мес). Это не опционально.

## Следствия

- Строка подключения к Neon — **pooled**, не прямая
- `packages/sim` исполняется только на сервере (см. GDD §3.1)
